Open-source security testing for defenders

Every finding has to survive being disproved before you see it.

Vajra tests the web apps, APIs and code you are authorised to test, then tries to knock down each result: is there evidence, is it in scope, does it reproduce, does it hold up under review? A pile of candidates goes in. A short list of proven findings comes out, ranked by what an attacker could reach, with everything it threw out and why.

$ vajra scan -config run.json -data data

          How it works

          Built to be pointed at real systems without fear.

          It tests web apps and APIs, reads source code, secrets and dependency advisories, and checks other tools’ SARIF reports against your code. Results go to Markdown or HTML reports, a local web interface, GitHub or Jira tickets, and a CI gate.

          6 of 6 planted flaws found and 0 of 6 decoys reported in its own lab. That lab is small and was written by the same team that wrote the checks, so treat it as a regression check, not an independent benchmark. The AI reviewer has so far been tested only against a stand-in.

          1. Deny by default

            No scope, no budget or no authorisation statement and the run does not start. Loopback, link-local and cloud-metadata addresses can never be targets, even if listed.

          2. One gate for every request

            Tools sit on a network with no route out. The only way through is the egress gate, which allows a connection only when the host, port and every resolved address are in scope, and logs each decision.

          3. A throwaway container per tool run

            Read-only root, no capabilities, no host environment, non-root, with memory, process and time limits. Vajra’s own requests go through the same sandbox and gate.

          4. Hard budgets

            Model tokens, model turns, sandbox runs and wall-clock time are all capped. A run that is cut short exits with an error and is not saved as a clean result.

          5. Prove it, or say why not

            Evidence, scope, reproduction, review. Confirmed findings get a blast radius and attack chains; refuted and unconfirmed ones stay in the report with the reason.
